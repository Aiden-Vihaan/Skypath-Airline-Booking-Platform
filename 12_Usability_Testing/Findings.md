# SkyPath — Usability Findings

## 1. Purpose

This document records usability observations generated through evaluation of the SkyPath prototype.

Findings should be based on observed participant behaviour rather than assumptions about what users may experience.

Each finding should describe:

1. What happened
2. Where it occurred
3. Why it matters
4. Severity
5. Evidence
6. Recommended design response

---

## 2. Finding Classification

| Category | Description |
|---|---|
| Navigation | Difficulty locating or understanding where to go |
| Comprehension | Difficulty understanding information or terminology |
| Interaction | Difficulty operating a component |
| Content | Missing, unclear, or poorly prioritised information |
| Feedback | Insufficient system response or confirmation |
| Error Prevention | Design permits avoidable mistakes |
| Accessibility | Interaction creates barriers for users with accessibility needs |
| Trust | Interface creates uncertainty about price, security, or consequences |

## 4. Emerging Findings

### UF-001 — Baggage Information Comprehension

**Status:** To be validated

The baggage flow should be evaluated for whether users can distinguish between included baggage allowance and optional additional baggage.

Particular attention should be given to:

- Weight limits
- Number of bags
- Carry-on versus checked baggage
- Additional cost
- Passenger-level baggage allocation

**Severity:** To be determined through testing.

---

### UF-002 — Fare Comparison Complexity

**Status:** To be validated

The fare-selection interface should be evaluated to determine whether users can compare fare benefits without relying on trial-and-error selection.

Potential risk areas include:

- Dense comparison information
- Hidden restrictions
- Price differences
- Ambiguous terminology

**Severity:** To be determined through testing.

---

### UF-003 — Booking Cost Transparency

**Status:** To be validated

The review stage should be evaluated to determine whether users understand how the final booking amount is constructed.

The evaluation should specifically examine whether additional baggage, seat selection, taxes, and other charges are sufficiently visible.

**Severity:** To be determined through testing.

---

### UF-004 — Post-Booking Discoverability

**Status:** To be validated

Check-in, refund, booking management, and other post-booking functions should be evaluated for discoverability within the global navigation structure.

**Severity:** To be determined through testing.

## 6. Cross-Task Patterns

Following testing, observations should be clustered across tasks to identify systemic issues rather than isolated interface problems.

Suggested analysis dimensions:

- Frequency
- Severity
- Task impact
- User confidence
- Recovery difficulty
- Number of affected user groups

---

## 7. Research Limitations

Prototype testing cannot fully reproduce production conditions.

The following limitations should be acknowledged:

- Prototype interactions may differ from a production system.
- Real airline inventory is not represented.
- Payment processing is simulated.
- Participant behaviour may be influenced by the testing environment.
- A small participant pool cannot represent all airline customers.
- Accessibility evaluation requires dedicated assistive-technology testing for definitive conclusions.

---

## 8. Conclusion

The final usability assessment should distinguish between observed evidence, design hypotheses, and unresolved questions.

The objective is not to demonstrate that the interface is universally usable, but to identify the highest-impact opportunities for improving the experience through evidence-based iteration.
