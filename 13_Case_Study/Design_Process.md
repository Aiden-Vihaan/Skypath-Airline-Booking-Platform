# SkyPath — Design Process

## Design Method

SkyPath followed an iterative user-centred design process.

The process was structured as:

**Research → Synthesis → Definition → Information Architecture → User Flows → Wireframes → Interface Design → Prototype → Testing → Iteration**

Each stage produced artefacts that informed the following stage.

---

## 01 — Research

The initial stage focused on understanding the airline-booking problem.

Research activities included:

- traveller-context analysis;
- persona development;
- journey mapping;
- content analysis;
- information-architecture exploration.

The primary output was a clearer understanding of the decisions users must make throughout booking.

---

## 02 — Persona Development

Personas were created to represent different traveller contexts.

The personas were not intended to represent every possible traveller.

Instead, they were used as design tools to test whether the system could accommodate different needs.

The primary personas included:

- Business Traveller;
- Family Traveller;
- Student Traveller;
- Senior Traveller;
- Accessibility-focused Traveller.

---

## 03 — Journey Mapping

The journey map connected user goals with actions, thoughts, emotions, pain points, and design opportunities.

This revealed that several problems were not isolated to individual screens.

For example, baggage decisions affected:

- price;
- passenger requirements;
- review;
- payment;
- post-booking management.

This supported designing the booking experience as a connected system rather than a sequence of independent pages.

---

## 04 — Information Architecture

The information architecture established the structural foundation of SkyPath.

Key artefacts included:

- Content Inventory;
- Card Sorting;
- Navigation Model;
- Sitemap;
- Information Architecture documentation.

The architecture prioritised user tasks such as:

- searching;
- comparing;
- booking;
- managing;
- checking in;
- modifying;
- refunding;
- upgrading.

---

## 05 — User Flows

Detailed flows were developed for high-impact tasks.

These included:

- Flight Booking;
- Check-in;
- Baggage;
- Loyalty;
- Refund;
- Seat Upgrade.

The flows explicitly modelled decision points and alternative paths.

This made it possible to identify potential dead ends and unnecessary transitions before detailed interface design.

---

## 06 — Wireframing

Wireframes were used to explore structure before committing to visual styling.

The wireframing system included:

- desktop layouts;
- mobile layouts;
- tablet considerations;
- reusable components.

The focus was on:

- hierarchy;
- spacing;
- navigation;
- information density;
- interaction patterns;
- responsive behaviour.

---

## 07 — Interface Design

The final interface design translated the structural decisions into a coherent visual system.

The design system considers:

- typography;
- spacing;
- hierarchy;
- buttons;
- forms;
- cards;
- navigation;
- status indicators;
- pricing components;
- accessibility.

Visual styling was deliberately kept subordinate to task clarity.

---

## 08 — Prototype

The prototype connected the major booking interactions.

Key prototype scenarios included:

### Scenario A — Book a Flight

Search → Compare → Select → Passenger Details → Seat → Baggage → Review → Payment → Confirmation

### Scenario B — Manage Baggage

Booking → Baggage → Existing Allowance → Add Baggage → Price Update → Confirmation

### Scenario C — Manage Booking

Booking → Manage Trip → Modify / Upgrade / Refund → Review → Confirmation

---

## 09 — Interaction Specification

Interaction details were documented through:

- Interaction Map;
- Transition Specifications;
- Prototype Link;
- Prototype Testing documentation.

The purpose was to describe not only what a screen looks like but also how the interface behaves when users interact with it.

---

## 10 — Usability Testing

The prototype was evaluated against representative booking tasks.

Testing focused on:

- task completion;
- navigation clarity;
- information comprehension;
- price transparency;
- baggage selection;
- review and payment;
- post-booking management.

Findings were documented and translated into recommendations.

---

## 11 — Iteration

Design iteration was based on observed usability issues and design review.

The iteration process prioritised problems according to their potential effect on:

1. task completion;
2. user confidence;
3. information comprehension;
4. accessibility;
5. interaction efficiency.

This helped prevent visual refinement from taking priority over fundamental usability issues.

---

## Design Decision Framework

When evaluating a design decision, the following questions were used:

1. Does this reduce cognitive effort?
2. Does it make an important decision clearer?
3. Does it expose information at the correct moment?
4. Does it support different traveller contexts?
5. Does it maintain consistency with the wider system?
6. Does it remain understandable across devices?
7. Does it reduce the possibility of user error?

---

## Process Outcome

The design process resulted in a connected UX system supported by documented research, information architecture, interaction flows, wireframes, prototype behaviour, and usability evaluation.

The process was therefore treated as an evidence-based design activity rather than a purely visual exercise.
